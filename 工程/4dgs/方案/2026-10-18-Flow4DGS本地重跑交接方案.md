# Flow4DGS 本地重跑交接方案

> 接手 agent：执行时使用 `superpowers:executing-plans`（若可用），逐项勾选并保留证据。本文件为交接设计，不表示训练已经开始。老板将本文件作为执行指令交给你后，在其确认的范围内连续推进，不逐步重复请求许可。

**Goal：**在本机 RTX 4060 Laptop 8GB 的 WSL2 中从头运行 Flow4DGS-SLAM，先完成 TUM walking_xyz 短片段验证与原帧率 10 秒重跑，交付可重载动态模型、完整帧渲染、演示视频及可追溯运行证据。

**Architecture：**独立源码、独立 Python 环境、独立 run 目录；环境验证→数据契约→全链路短验证→10 秒运行→模型重载与展示验收。旧模型仅作来源明确的对照，不用于冒充本轮重跑。

**Tech Stack：**Windows / WSL2 Ubuntu 22.04、NVIDIA CUDA、PyTorch、官方 Flow4DGS-SLAM、RAFT、YOLOv9e-seg、项目自定义 Gaussian rasterizer / simple-knn。

**设计来源：**本文件包含完整设计；证据上下文见同目录上级的 `总流程记录.md`、`问题留存.md`、`总任务总纲.md`。用户已明确方向为重新运行、优先核查本机能力；walking_xyz 首跑及后续候选是本方案建议，提交本文件执行时须按老板给出的实际范围判断授权。

## 一、总路线与边界

1. 隔离环境并验证 CUDA 扩展，确定项目是否能在本机实际执行。
2. 准备 walking_xyz 原始 RGB-D、标定及参考轨迹，冻结 10 秒输入清单。
3. 从同一片段取前 30 个有效观测完成全链路短验证，测显存和各阶段耗时。
4. 验证通过后从头运行完整 10 秒片段，保留原帧率观测并生成全部帧渲染。
5. 重载模型检查动态变化和代表视角，导出演示视频及验收报告。

首轮范围是 **一条序列、一个 10 秒片段、一套官方基线配置**；不是全数据集评测。20–30 帧试验中的本方案固定采用 30 个有效 RGB-D 观测，不将它视为质量验收。不得未经确认扩展全部 TUM/BONN、租用 GPU、关闭其他人的进程、修改系统驱动或重构无关项目。

## 四、分步执行与检查门

### 阶段 A：隔离环境与源码锁定

目的：先证明扩展能在本机执行，避免下载完数据才发现平台不兼容。

- [ ] 读取项目 AGENTS 和当前模型过程记录；检查已有运行进程及目录，不重复启动。
- [ ] 刷新 GPU/显存、主机和 WSL 内存、实际宿主盘空间；不主动关闭用户程序或改变 WSL 资源配置。
- [ ] 独立获取官方源码与必需子模块，记录 commit、子模块版本、工作区状态及补丁；不复用其他项目可变源码。
- [ ] 在隔离环境安装兼容依赖与官方权重；核对权重真实下载成功、路径和 SHA256，禁止将 HTML 错误页当权重。
- [ ] 验证 torch CUDA 张量运算、RAFT 和分割单次推理、Gaussian rasterizer 前向/反向、simple-knn 的实际 GPU 执行；仅 import 成功不算通过。
- [ ] 保存依赖版本、编译日志和命令。接口兼容补丁限定在隔离源码，保存 diff，不顺带改变损失、优化次数或模型结构。

通过门：全部必需 GPU 操作执行成功且结果有限。遇到 OOM/编译失败先诊断，不自动以禁用动态模块替代成功。

### 阶段 B：数据与片段冻结

目的：保证观测、时间、位姿和模型的对应关系可复查。

- [ ] 只准备 `rgbd_dataset_freiburg3_walking_xyz`；使用官方脚本对应的 TUM 下载地址，先检查归档和解压空间，保留校验与下载日志。
- [ ] 按项目实际数据加载器确认 RGB-depth 时间关联、深度尺度、标定、参考轨迹匹配、无效观测处理与相机坐标约定。
- [ ] 从有效关联序列起始时间取 `[t0,t0+10秒)`；保留该范围全部有效观测，按时间排序，记录源 RGB/depth 路径、两者时间戳、关联差、帧号及 GT 匹配。
- [ ] 记录原始/有效/排除数量及原因，不硬凑 298 帧；原包的 298 输入、297 输出不是新运行必须伪造的数量。
- [ ] 审计加载器是否隐含降采样；不得将设置 `FRAME_RATE=32` 或显示播放 FPS 当作保留原始观测的证据。
- [ ] 冻结源码、权重、配置、输入清单及数据校验；固定 seed=0，记录无法保证确定性的 CUDA 算子。

通过门：片段输入可逐项追溯、时间单调、RGB-D 和 GT 关联明确。GT 用于评估及官方协议规定的初始化；不能把每帧 GT 替代估计位姿来宣称跟踪成功。

### 阶段 C：30 帧全链路短验证

目的：以低成本发现真实执行、保存、精修、恢复和导出问题。

- [ ] 从已冻结片段取前 30 个有效观测，以官方动态配置运行；继承配置的优先级以当前源码解析为准。
- [ ] 先阅读当前入口和 `--help` 确认参数，不原样复制旧包命令；特别核对 `--save_results=0` 的行为，确保保存完整动态模型、相机与必要状态。
- [ ] 覆盖跟踪、动态建图、颜色精修、评估、模型保存和单独进程重载；保留实际执行迭代数。
- [ ] 测记录初始化、各帧处理、mapping、refinement、渲染和导出的 wall time；同步采样 GPU 显存及系统内存。记录帧号、关键帧数与高斯数变化。
- [ ] 检查动态参数、时间相关旋转/不透明度的保存加载；选不同时间重渲染，确认不是只读了静态 PLY。

通过门：无未解释异常、模型可重载、RGB/depth 有限、帧数差异可解释、动态管线实际执行。短验证的画面不能证明最终质量，短验证峰值也不能证明 300 帧不溢出。

### 阶段 D：原帧率 10 秒完整运行

目的：得到本轮独立重跑的可展示动态模型和本机实测成本。

- [ ] 以新的 run ID 从头执行冻结的完整 10 秒片段；不把 30 帧已优化状态拼到正式运行，也不加载旧包模型冒充重跑。
- [ ] 保留官方 tracking/mapping 次数及 1500 次颜色精修，除非源码核查发现实际协议不同并向老板说明。不能为赶工悄悄减迭代或抽帧。
- [ ] stdout/stderr 无缓冲写日志；每 10–30 秒更新阶段、已完成/总帧数、PID、关键帧、高斯数量、资源和最近更新时间。
- [ ] 初始 ETA 标为待测；出现稳定映射样本后，按初始化+处理剩余帧+精修+导出分段估算，标记显存/高斯增长带来的不确定性。
- [ ] 如技能可用，启用 `reproducible-long-experiment` 和 `codex-quota-heartbeat`；启动重活前检查额度，此后300秒检查。无明确goal请求不创建goal；额度查询不可用时保留状态并告知，不另造未经授权的训练任务。
- [ ] 出现 OOM 保留日志、帧号、配置和峰值，结束该次失败运行。先判断其他进程占用/存储/工具链问题；若需要降低分辨率、抽帧、改点密度或关闭模块，作为新协议提交老板确认，不覆盖失败配置。

恢复门：恢复前核对 manifest/config/input 哈希、进程和检查点；匹配才继续，不匹配另建 run。不得留下无人管理的训练进程。只对本任务拥有的进程进行停止或恢复。

### 阶段 E：重载、展示和验收

目的：区分程序完成、重建可用和展示质量。

- [ ] 在独立进程加载本轮模型和全部动态参数，分别核验起始、中段、末段及动态明显的关键帧。

- [ ] 检查模型、日志、退出码、处理计数和 SHA256；报告成功/失败/跳过/未验证内容，确认本任务必要进程结束。
