### 1.3 关键更正：`pose.txt` 没有坏

包内说明称 `pose.txt`"397 个位姿、297 个旋转矩阵奇异、帧间位移中位数 5.01 m，请勿逐帧索引"。**实测不是这样**：

| 检查项 | 实测 |
|---|---|
| 行数 | 1192 行 = **298 个 4×4 矩阵**（每帧 4 行，严格的逐帧顺序） |
| 旋转矩阵行列式 | min 1.000000、max 1.000036，**奇异数 0**，负行列式 0 |
| 正交性误差 | 最大 4.5×10⁻⁵ |
| 相邻帧位移 | 中位 1.36 cm，最大 4.85 cm（正常行走尺度） |
| 对照 TUM 真值 | SE(3) 对齐后 **RMSE 2.65 cm、中位 2.18 cm、最大 6.08 cm** |

结论：`pose.txt` 是**本轮估计的相机轨迹（c2w）**，精度与包内声称的 ATE 2.24 cm 吻合，可以逐帧索引。说明文档的"损坏"判断是把每 12 个数字当成一个位姿造成的误读。

### 1.4 关键更正：官方渲染用的是估计位姿，不是 GT 位姿

- 官方 `eval_rendering` 用的是 `self.frontend.cameras`，即**跟踪优化后的位姿**；`pose.txt` 正是它的逆（c2w）。
- 包内 `scripts/render_main_view.py` 用 `dataset[idx][2]`（GT 位姿）渲染，frame 0 得 18.55 dB，而官方 before_opt 是 22.97 dB。
- 两者差 4.4 dB 的主因是**位姿来源不同**（模型是拟合自己的估计位姿建起来的，用 GT 位姿等于把相机挪了 2 cm），不是投影矩阵。投影矩阵用 `getProjectionMatrix2` 仍然是对的。

**这条更正直接决定复现路线**：重渲染必须喂 `pose.txt` 的估计位姿，才能对得上官方图。

### 1.5 依赖分层的实测结论

- 纯渲染路径（`GaussianModel` + `Camera` + `render`）只需要 `simple_knn` 和 `diff_gaussian_rasterization` 两个 CUDA 扩展，**不需要 pytorch3d、不需要 ultralytics**。
- `pytorch3d` 只被 `utils/slam_backend.py`、`utils/deform_utils.py`、`utils/time_utils.py` 引用 → **只有训练级复现才必须编译它**。
- RAFT 权重本地已有：`D:\桌面\image\gpt-6\工程\医学三路线复现\20261009\outputs\fullflow\source\Deform3DGS\submodules\RAFT\pretrained\raft-things.pth`（21,108,000 字节，标准 raft-things）。
- `yolov9e-seg.pt` 本地没有，但 GitHub 可达（302），需要时下载即可。

## 二、路线分步

### 阶段 P1：精简环境（只为"渲染"这条链路）

**目的**：用最小依赖把渲染跑通，尽早暴露 CUDA 扩展与 PyTorch 版本问题。

- 已建 venv：`/home/ad/flow4dgs-local/env/flow4dgs`，PyTorch 2.1.2 + cu121（适配 Ada sm_89；官方推荐的 torch 1.13.1+cu117 不支持 sm_89，这是记录在案的偏离）。
- 只装渲染所需：`opencv-python`、`open3d`、`matplotlib`、`plyfile`、`trimesh`、`scipy`、`einops`、`munch`、`pyyaml`、`tqdm`、`Pillow`、`torchvision`。
- 编译 `submodules/simple-knn` 与 `submodules/diff-gaussian-rasterization`，`CUDA_HOME=/usr/local/cuda-12.4`、`TORCH_CUDA_ARCH_LIST=8.9`。
- **暂不编译 pytorch3d**（约 20–40 分钟，且 7.6 GB 内存需 `MAX_JOBS=2`），留到 P4。

**验证门**：两个扩展能实际在 GPU 上前向/反向执行且结果有限；`distCUDA2` 与高斯光栅化各跑一次真张量，仅 import 成功不算通过。

### 阶段 P2：模型级复现（不训练，核心验证）

**目的**：证明"本机 + 官方代码 + 本地模型"能复现出包内那 297 张官方渲染。

做法：
1. 用 `model/config.yml` 作为配置，`Calibration.start=0/end=298`，数据指向 WSL 里刚下的 walking_xyz。
2. `load_ply(model/point_cloud.ply)` + `load_offsets(model/offsets.pth)`，重构 `GaussianModel`（`sh_degree=0`、`dynamic_model=offset`、`nframes=298`）。
3. 相机位姿来自 **`pose.txt`（估计位姿，c2w → 取逆得 w2c）**；投影矩阵用 `getProjectionMatrix2(0.01,100.0,cx,cy,fx,fy,640,480)`。
4. 逐帧 `render(cam, g, pipe, bg, dynamic=False, dx=dxyz, ds=0, dr=0)`，`dxyz` 按关键帧序号插值（不是按帧号索引 `_delta_xyz`）。
5. 同时渲染 `before_opt` 与 `after_opt` 两种状态（`after_opt` 用最终模型；`before_opt` 需用 `final_before_opt` 的点云 —— 本包未提供，因此 before_opt 只能引用包内图，不重渲，如实标注）。

**验收门（关键）**：重渲染结果与包内 `frames/after_opt/{i}_color.png` 逐帧 PSNR。
- 同一路径、同一模型、同一位姿 → 中位 PSNR 应 ≥ 30 dB（理想 ≥ 35 dB）。
- 若中位 < 25 dB：按顺序定位 —— ① 位姿是 GT 还是估计；② `ds/dr` 是否传了 0 而不是 None；③ `dygs` 动态高斯的 GMM 不透明度/旋转是否生效；④ 投影矩阵主点；⑤ 背景色（官方 `[1,1,1]`，脚本用 `[0,0,0]`，这一条本身就会压低 PSNR）。
- 若 ≥ 30 dB：渲染链路判定通过，才进入 P3。

### 阶段 P3：展示件（渲染链路通过后）

- 深度：导出**原始 float 深度**（16-bit PNG 或 .npy，米制）与 jet 着色预览分开，不把 jet 当米制。
- 对照：before_opt（包内官方图） vs after_opt（重渲或包内图）逐帧拼版。
- 视频：按原始时间戳 30 fps，297 帧 = 9.9 秒；主视频用 after_opt 全帧，附 before/after 对比版。
- 新视角：沿光轴/横移 ±5 cm、绕光心 ±3° 的有限幅度渲染，明确标注"训练视角附近的小幅空间渲染"，不宣称自由视角泛化、不承诺 360° 完整人物。

### 阶段 P4：训练级复现（本地真跑）

前置：P1/P2 通过、pytorch3d 编译成功、`yolov9e-seg.pt` 下载好、RAFT 权重就位。

1. **30 帧全链路短验证**：取 `start=0,end=30`，跑完跟踪→建图→颜色精修→评估→模型保存→独立进程重载，测显存与各阶段耗时。
2. **298 帧完整重跑**：新 run ID，从头执行，不加载旧包模型；保留官方 tracking/mapping 次数与 1500 次颜色精修；无缓冲日志 + 心跳（10–30 秒）。
3. **对比**：ATE、PSNR/SSIM/LPIPS、高斯数、关键帧数、总耗时、峰值显存，逐项与原包（ATE 2.24 cm、PSNR 21.20→25.62、63,273 高斯、62 关键帧）比较，差异要能解释。
4. 恢复能力：原项目不支持完整中途恢复（`frontend_cameras.pth` 从未被保存），若要断点续跑须先补最小恢复路径并做中断核验，不能用"重新从头跑"冒充续跑。

## 三、结尾：执行顺序与验收

1. **P1 环境**（约 40 分钟，含 torch 轮子下载）→ 门：两个 CUDA 扩展真跑通。
2. **P2 模型级复现**（约 1 小时）→ 门：与官方 after_opt 逐帧中位 PSNR ≥ 30 dB。
3. **P3 展示件**（约 1 小时）→ 门：视频可播、深度数值与着色分开、新视角标注边界。
4. **P4 训练级复现**（30 帧验证 + 298 帧，1–3 小时窗口，尚无本机实测）→ 门：指标差异可解释、无 OOM 未解释失败。
5. **P5 归档**。

最终可交付：一条可复用启动入口、锁定配置与依赖、数据清单、动态模型、全帧结果、视频、运行证据、验收报告。

验收边界（必须写进报告）：
- 包内 `before_opt` 只有图、没有 `final_before_opt` 模型，**无法独立重渲**，只能引用。
- 训练观测视角的重建质量不等于新视角泛化。
- 单目轨迹未观测区域不要求凭空补齐。
- 8 GB 显存下 298 帧是否 OOM 仍是未知数，短验证的峰值不能证明长序列不溢出。
